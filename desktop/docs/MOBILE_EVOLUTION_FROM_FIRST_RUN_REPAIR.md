# 데스크톱 첫 실행 복구에서 모바일로 이어갈 개선

2026-10-06의 0.2.49-desktop 수정에서 얻은 모바일 개선 후보입니다. Android 구현·기기 확인 결과가 아닙니다. 초기 데스크톱 후보는 파일 준비 후 실제 모델 로드에서 실패했습니다. 후속 후보는 같은 실행파일의 실제 Windows CPU 시험에서 공식 7개 파일의 새 준비와 별도 구동 작업 22개 확인을 통과했습니다. 초기 실패와 후속 성공을 구분하며, 파일 무결성 확인과 실제 구동 판정을 따로 해야 한다는 사례로 기록합니다. 사람 품질·실제 마이크·7초 지연·300명 운영이나 Android 성능 확인은 아닙니다. 모바일의 기존 공개 패키지와 배포 서명은 별도 이력으로 유지합니다.

| 데스크톱에서 다룬 문제 | 모바일에서 적용할 방향 | 모바일에서 필요한 확인 |
| --- | --- | --- |
| 파일 준비를 실행 가능으로 오인함 | 모델 파일의 크기·해시·저장 공간 확인과 실제 런타임·메모리·언어별 구동 판정을 분리합니다. 파일만 받은 상태를 명확히 표시합니다. | 대상 Android 버전·ABI·RAM·추론 엔진에서 실제 로드와 첫 추론을 확인합니다. |
| 느린 연결에서 다운로드가 중단됨 | 용량·이용조건을 보여준 뒤 명시적으로 동의를 받습니다. 완료 파일 재사용, 지원 서버의 범위 이어받기, 수신 유휴 제한과 HTTP 오류별 제한적 재시도를 검토합니다. | 모바일 데이터·Wi-Fi 전환, 앱 백그라운드·종료·재시작, 절전 상태와 부분 파일 무결성을 시험합니다. 전체 다운로드 시간이 길다는 이유만으로 실패시키지 않습니다. |
| 어디에서 모델 준비가 막혔는지 알기 어려움 | 다운로드·검증·로드·첫 추론·언어별 확인을 단계로 표시하고 소요시간·오류 범주를 기록합니다. | 공개 진단에는 개인 음성·원문·API 키·기기 개인 경로를 넣지 않는지 확인합니다. |
| 모델 기동 중 설정을 바꿈 | 기동과 환경 구성 중 모델·가속 방식 변경을 막고, 요청 대기부터 완료·실패까지 같은 규칙을 적용합니다. | 설정 저장·앱 재시작·작업 재개 때 표시와 실제 사용 설정이 일치하는지 확인합니다. |
| 큰 CPU 모델을 처음부터 선택함 | 기기별로 검증한 시작 모델을 제공하되 기존 사용자의 설정 변경은 명시적 선택으로 진행합니다. 인식 모델만 바꿀 때 번역 모델·다른 설정을 유지합니다. | 작은 모델의 실제 언어별 정확도·메모리·지연을 측정하고, 준비 확인과 품질 판정을 구분합니다. |
| 출력 존재를 품질·수용량 완료로 오인함 | 기능 연결, 사람 평가 정확도, 실제 마이크부터 청취까지 지연, 접속 수용량을 따로 표시합니다. | 합성 시험 WAV의 비어 있지 않은 출력만으로 인식 정확도·7초 지연·300명 운영 완료를 판정하지 않습니다. |

Windows용 공식 GGML 모델 파일, 단일 EXE, DLL·Microsoft VC++ 설치/UAC 경로는 데스크톱의 구성입니다. 모바일에는 Android ABI와 네이티브 엔진, 모델 형식·라이선스·저장 정책에 맞는 구성을 검토하며 Windows 패키지를 그대로 옮기지 않습니다. 데스크톱 Small Q5의 CPU 무음 첫 추론·고정 합성 WAV 음성인식 결과와 무음 환각 관찰을 Android 성능·품질 결과로 사용하지 않습니다.

모바일의 다음 검증은 실제 기기에서 파일 준비와 재사용, 시작 모델 로드·첫 추론, 언어별 음성 출력, 실패 복구를 먼저 확인하는 것입니다. 실제 마이크·LAN 청취·정확도·연속 운영·7초 지연과 규모 확대는 독립된 후속 시험으로 유지합니다.
