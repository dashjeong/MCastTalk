# MCastTalk Gemma 모바일 적용 검토

검토일: 2026-10-03 KST. 판정: 모델별 선택을 유지하며 E4B를 모든 기기의 기본값으로 승격하지 않는다. 기존 MCastTalk의 입력·번역·음성·방송 구조를 개선한다. 이 문서는 적용안이며, 신규 모델의 배포 완료 또는 통번역 품질 보증서가 아니다.

## 1. 제출 의견에 대한 판단

기존 앱을 유지하고 로컬 모델·선택적 온라인 경로·용도별 문체를 개선하자는 방향은 적절하다. 그러나 의견의 S26 Ultra 전제는 현재 시험 환경과 다르다. 실제 물리 시험은 S23+ SM-S916N/API 36이며, 최근 비교시험은 API 35 ARM64 에뮬레이터다. 제조사의 S26 수치를 S23 통역 지연으로 인용하지 않는다.

Whisper 추가는 별도의 음성인식 비교 과제다. 원문이 이미 표시된 뒤 번역이 나오지 않는 증상에는 번역 요청·대기열·생성 종료·복구를 먼저 조사해야 한다. 모델 파일 교체를 위해 정상 입력 경로를 다시 만드는 것은 권하지 않는다.

E4B의 Android `.litertlm`과 MTP 지원은 공개되어 있으나 효과는 작업에 따라 달라진다. 디스크 파일 크기와 실행 중 메모리 사용량도 다르다. MCastTalk는 호환 단말에서 GPU 경로를 실제 확인하고, MTP 요청 여부와 실제 가속 여부를 구분해야 한다. [공식 E4B LiteRT-LM 배포 자료](https://huggingface.co/litert-community/gemma-4-E4B-it-litert-lm)

TranslateGemma는 55개 언어 번역에 특화되어 있고 일반 Gemma 4와 템플릿·약관이 다르다. 현재 확인한 LiteRT Community 변환본은 MediaPipe **웹** 배포용이며 Mac Chrome 측정치를 제공한다. 이 자료만으로 현행 Android LiteRT-LM 0.16.1에서 바로 교체 가능하다고 판정할 수 없다. Android 로딩·토크나이저·입출력·취소·메모리·라이선스를 별도로 검증한다. [공식 TranslateGemma 카드](https://huggingface.co/google/translategemma-4b-it), [공개 웹 변환본](https://huggingface.co/litert-community/TranslateGemma-4B-IT)

E2B 48건에 대한 협업자의 AI 예비 검토는 PASS 26 / MINOR 10 / MAJOR 12, 별도 18건은 11 / 3 / 4다. 기능 완료와 의미 정확도는 다르다. 이는 합성 문장에 대한 AI 검토이며 사람 평가나 전체 사용 환경의 정확도 비율이 아니다. Codex는 원본·해시와 주요 오류를 재확인했다. 직급 대응·일본어 경어 등 해석 여지가 있는 항목은 확정 오역과 구분한다.

확인된 중요 사례는 중국어 요청에 영어 출력(RC01), 일본어 출력의 원화→엔화 변경(MC01), 원문 그대로 인용하라는 오기의 표기 변경(MC05), 중국어 부정문을 반문으로 바꾼 결과(MC09)다. 복수 통화·복수 인용·행위자 관계는 단순 정규식으로 추측 보정하지 않는다.

공통 출력 검증·좁은 보정을 E2B에도 적용한 후, 별도 정확 APK에서 회의 18건을 다시 실행했다(JUnit 52.057초). Codex가 수정 전후 동일 원문·문맥·스타일 18건을 대조한 결과, 변경 출력은 정확히 3건: MC01 일본어 OFF의 원화 표기 복구, MC05 일본어/중국어 OFF의 명시 인용 복구다. MC09 중국어 ON의 부정→반문 오류는 남아 있다. 따라서 18건 완료를 의미 품질 전체 합격으로 표시하지 않는다.

같은 수정 후 회복 시험은 48건 중 33건 시도·32건 완료·1건 실패·15건 미실행이며 정리가 완료됐다. RC01 중국어 OFF가 1,479 ms에 `IllegalStateException`으로 실패했고, 실제 JUnit 로그에서 `GEMMA_TARGET_SCRIPT_MISMATCH`를 확인했다(전체 JUnit FAIL, 76.154초). 잘못된 목표 언어를 검출한 증거이며, 해당 요청의 실제 대체 번역·음성 복구 성공을 입증하지 않는다. 수정 후 회의 결과 SHA-256은 `26117c5f5c44272e4e8e0ea2cb251c4a1ffd0018493665a4975790fe9d993a69`, 회복 결과는 `471bf9df4564c9e8abb1cb33153fcb1d6f44c6c0ec66fa66928f742e9e12af36`다.

원본 증거는 로컬의 `build/evidence/domain-learning-20261002/`에 보존한다. 아래 SHA-256은 합성 문장 시험 결과이며 사용자 음성이나 키를 공개하는 자료가 아니다.

- E2B 회복 48건: `emulator-domain-recovery-dev-offline-standard-1790961141494.json`, `3ce19012b7185878a1728680229c2250c66678aafe2e97614c46cc43db1feebb`
- E2B 회의 18건: `emulator-domain-meeting-offline-standard-1790961448757.json`, `6519231df4153fc035434ce35dddbe6eac1c9199aeec3a241b528e69cac46d97`

## 4. 우선 적용안

1. **기존 선택권 보존.** E2B/E4B와 준비된 언어팩을 유지한다. 이미 받은 모델을 언어 변경마다 다시 받지 않는다. 모델 변경은 번역 계층에 국한하고 정상 음성 입력·방송 제어를 보존한다. 자동 추천은 실기기 측정 후 제공하며 사용자가 선택한 모델을 몰래 변경하지 않는다.
2. **원문 우선 문맥.** 현재 번역 대상과 최근 확정 원문·확정 용어·도메인 참고를 구분한다. 이미 승인한 번역은 일관성 참고로만 사용한다. 방송/입력 세션 종료 시 대화 문맥을 초기화한다. 입력 의미 단위는 보존하고 참고자료부터 예산을 줄인다. 검색된 코퍼스 활용은 가중치 학습이나 강화학습 완료가 아니다.
3. **의미 보존 후 출력.** 목표 언어와 원문 복사 여부를 공통 검사한다. 유일하게 정합 가능한 단일 통화 표기·명시적 단일 원문 인용만 좁게 보정한다. 원문·숫자·사용자 확정 문장·코퍼스를 바꾸지 않는다. 실패는 해당 언어의 기존 복구 경로로 격리하고 실제 사용 엔진과 이유를 표시한다. 복구 번역 품질·비무음 음성은 별도 시험한다.
4. **E4B 지연 진단.** 준비·대기열·첫 출력·생성 완료·TTS 첫 PCM·웹 첫 PCM을 나눠 측정한다. GPU 우선 및 호환 MTP를 비교하고 참조 문맥을 제한한다. 실시간 10초 실패 상한을 60초로 늘려 성공처럼 보이지 않는다. 별도 60초 평가는 품질 분석용이며 제품 대기시간이 아니다.
5. **연속 처리량.** 번역과 재생 큐를 분리해 앞 문장 낭독 중 다음 번역을 처리한다. 준비된 엔진은 재사용하되 E2B/E4B를 동시에 적재해 메모리를 낭비하지 않는다. 문장 번호·세션 번호로 늦은 결과와 중복 재생을 차단한다. 동시통역도 새 문장의 의미 확인과 추론 시간이 필요하므로 지연 0을 약속하지 않는다. 연속 발화에서 큐 대기가 계속 증가하지 않는지를 언어별로 확인한다.
6. **목적과 격식 분리.** 대화/현장 안내/발표/문서의 목적과 정중함·공식성을 별도 정책으로 설계한다. 화면 기본값은 자동으로 유지하고 상세 설정에서 노출한다. 자연스러운 의역도 부정·조건·행위자·금액을 변경해서는 안 된다. 현재 AUTO/FORMAL/CONVERSATIONAL을 그대로 목적 분리 완료라고 표시하지 않는다.

온라인은 사용자가 명시적으로 활성화한 API 경로에서만 사용한다. 실패 복구를 이유로 비공개 원문·음성·로그를 외부로 자동 전송하지 않는다. Gemini 등 비교 결과는 별도의 참고 평가이며 인간 정답으로 취급하지 않는다.

## 5. 신규 확인한 E4B 실행 개선 후보

현행 **LiteRT-LM 0.16.1** AAR의 공개 API와 같은 버전 upstream 소스에서 `ConversationConfig.enableResponseFormat`, `ResponseFormat.json(schema)`, 비동기 요청의 `responseFormat`을 확인했다. 새 SDK를 추가하지 않고 번역 결과 JSON 형식만 제한하는 비교시험을 할 수 있다. [정확 버전 설정 소스](https://github.com/google-ai-edge/LiteRT-LM/blob/v0.16.1/kotlin/java/com/google/ai/edge/litertlm/Config.kt), [정확 버전 요청 소스](https://github.com/google-ai-edge/LiteRT-LM/blob/v0.16.1/kotlin/java/com/google/ai/edge/litertlm/Conversation.kt)

이 기능은 형식 오류·불필요한 생성의 개선 **후보**다. 번역 의미나 속도 향상, 현재 60초 지연의 원인 해결을 입증한 것은 아니다. 동일 frozen 문장에 제약 OFF/ON을 비교하고 정답·원문을 schema에 넣지 않는다. 네이티브 종료 콜백 전에 엔진을 닫거나 큐 소유권을 반환하는 방식은 금지한다. 합격 전 기본값으로 활성화하지 않는다.

후속 실제 비교는 같은 서명 APK에서 RC01 영어·도메인 OFF 한 건씩 수행했다. JSON 제약 ON은 첫 출력 7,240 ms·60,051 ms 시간 초과, 제약 OFF는 첫 출력 5,532 ms·43,333 ms 완료였다. OFF 결과는 수정 지시와 본인의 직접 수정 약속을 구분했지만 원문에 없는 남성 대명사 `he`를 선택했다. ON→OFF 순서·각 1회이며 모델 준비 시간도 16,815/12,351 ms로 달랐다. 제약 ON의 성능 개선은 입증되지 않았으므로 기본 OFF를 유지한다. CPU에서 항상 실패한다고 단정하지 않으며, 43초 완료를 실시간 합격으로 계산하지 않는다.

이 비교의 정확 product APK SHA-256은 `2e699db1554c456aa13e0fa861b7e3097cddd2898afa7814c56ab4b406bb6e48`, test APK는 `5af68436fab006a8c15e5e7469feed25d151ee4850ca80846ed21694644bb9cc`다. ON 결과 SHA-256은 `af4b2334d11ebf92796a9364d529563d2549da6b518bdb747d8ef2cf82b3869c`, OFF 결과는 `4a8489f5c544a9080c44acd3b04d0e33fd5c6474d4fe8f254bde4abcf368285e`이며 모두 cleanup이 완료됐다. Codex가 원본·해시·입력과 분모를 확인했다.

## 6. 추천 승격·배포 판단

후속 E2B 의미 보호 검증에서 첫 독립 16행은 12완료/4실패, 별도 새 독립 12행은 7완료/5실패였다. 완료 결과에도 일본어·한글 숫자 혼입이 남았고 ML Kit 비교 출력에는 화자·보증금·항공료 오류가 확인됐다. 관측 가능한 통화 파서 누락과 인용 부정 지시의 과잉 차단을 보완하고, 세 가지 의미 검토 오류는 해당 요청만 자동 대체 출력 없이 언어별 실패로 처리한다. 최종 에뮬레이터의 실제 E2B 두 요청 시험에서는 인용 검토 실패 뒤 다음 번역이 1,135 ms에 완료됐다. 이 결과는 오역의 정답 생성이나 실기기 음성 품질 합격이 아니다. 변경 전 독립 표본을 수정 후 비공개 품질 합격으로 재사용하지 않는다. [추가 의미 보호 검수 보고서](validation/0.2.46-beta-d/PROTECTED_MEANING_REVIEW_REPORT.md)

한영·한일·한중 간체의 동일 원문·문맥·용어·스타일로 모델별 결과를 비교한다. TRAIN/DEV/TEST를 분리하고 개선에 사용한 DEV를 새 비공개 평가처럼 계산하지 않는다. 공식 모델별 권장 템플릿을 사용한 제품 경로 비교와 동일 설정의 순수 모델 비교도 구분한다.

핵심 부정·조건·화자/행위자·통화·숫자·명시 인용 오류가 남으면 고품질 기본 모델로 승격하지 않는다. 새로운 미사용 문장과 실제 음성 입력에서도 반복 검증한다. 한국어 원문 인식 오류는 번역 오류와 따로 기록한다.

최종 APK 기준으로 S23급 준비된 단일 언어 STT 확정→**웹** 첫 PCM p95 2,000 ms, 원음·언어별 실패 격리, 중지/재시작·오프라인·장시간 안정성과 사람 청취를 검증한다. 현재 측정은 이 전체 게이트를 통과하지 않았다. 최신 공통 출력 보정·응답 제약 비교의 검증 결과는 별도 보고서에서 실제 APK와 함께 갱신한다.

현재 권고는 **E2B 선택 유지 + 실기기 합격 조건의 E4B 추천 + TranslateGemma 독립 비교**다. 현재 자료만으로 특정 모델을 모바일 통번역의 최상·99%·상용 품질 검증 완료로 표현하지 않는다.
