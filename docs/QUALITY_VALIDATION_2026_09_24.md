**공개 재배포 보류: 품질 게이트 미충족.** 사용자의 공개·커밋 요청은 유지된다. round10 수정 네이티브 APK에서 네이티브·숫자·EOF 6개와 방송·시험 버튼·파일 여정 3개가 실제 통과했다. 지정 영상 2건의 최종 APK 재시험도 완료했고 34개 의미 묶음의 번역 요청이 모두 완료됐다. 선별 의미 결함 5개는 부분 개선 2개·동일 오류 3개·완전 해결 0개로, 전체 기능·음성·의미 정확도·장시간 안정성의 통과 결과는 아니다. 공개 기준은 0.2.42 복구 상태를 유지하며, 이는 0.2.42의 번역 품질 보증을 뜻하지 않는다. 마이크 전체 여정은 재시험하지 않아 이전 실패·미입증 상태를 유지한다.

실행 완료·정상 종료·전사 존재·숫자 보존·의미 정확도를 서로 다른 판정으로 기록한다. 자동 자막, 모델 언어 확률, JUnit의 단순 `OK` 문구만으로 품질 통과를 선언하지 않는다.

## 무출력 7건과 음원 적합성

ko12·ko13·ko21·ko22·ko25·ko28·ko30은 원래 시험에서 공급자 콜백 0건, 정상 입력 EOF였다. ko12·ko13은 의미 조립·자동 재시작을 거치지 않는 직접 Moonshine 입력에서도 무출력이었다. 초기 JNI 진단에서도 ko01 양성 대조는 고유 final 29개였으나 ko12는 네이티브 전사 행 자체가 0개였다. 검사한 JNI 반환 코드에 오류가 없었다는 사실이 VAD 내부 처리까지 모두 성공했다는 증명은 아니다.

같은 ko12 첫 12초에서 VAD 0.58은 전사 행 0개, 진단용 VAD 0은 최종 행 1개였다. VAD 0 결과는 짧은 구절의 반복으로 **환각 의심·품질 실패**다. 해당 실행의 JUnit 통과는 진단에서 출력 존재를 관찰했다는 뜻이며 복구 완료가 아니다. 제품 VAD 임계값을 0으로 바꾸는 수정은 채택하지 않았다.

고정된 공식 Whisper small을 로컬에서 사용한 초기 3구간·추가 8구간, 총 **11개 진단 호출**이 완료됐다. 각 구간은 12초이며 ko01 양성 대조는 한국어 추정 약 97.98%와 문장 형태의 출력을 보였다. ko12 네 위치와 나머지 실패 6건의 한 위치에서는 음악 표식·빈 결과·강한 반복 등 신뢰하기 어려운 결과가 나왔다. 추가 8구간의 한국어 추정은 1.11~3.08%였다. 이 값은 모델 추정이며 실제 언어·정답률이 아니다.

배포자 자막은 한국어 중심이었지만 이것만으로 발화 언어·음성 존재·시간 정렬을 보증할 수 없다. 비음성·음악, 자막/음원 불일치, 두 인식기 모두 어려운 음원일 가능성을 분리해야 한다. 사람 청취를 하지 않아 어느 원인도 확정하지 않았다. 기존 7건은 삭제·성공 처리하지 않고 적합성 미확정의 난음원·환각 저항성 표본으로 보존한다. 일반 한국어 품질 평가에는 별도로 확인한 연속 발화 표본을 추가해야 한다. Whisper 결과를 앱의 성공 또는 인증된 정답으로 대체하지 않는다.

## 네이티브 기준판 실패와 round10 수정판 재시험

기존 SDK에 320샘플 프레임의 합성 0 PCM을 가속 입력했다. 예열은 1,500프레임, 측정은 12,000프레임이며 실제 벽시계 8시간 시험이 아니다.

| 진단 | 실제 기준판 결과 | 해석 |
|---|---|---|
| 초기 탐색 메모리 측정 | 네이티브 heap **+38,126,080 bytes** | 미소비 입력 버퍼가 포함되므로 순수 누수 규모로 사용 불가 |
| 25프레임마다 강제 전사로 입력을 비운 재측정 | **+19,776,000 bytes**, 한도 8,388,608 bytes 초과 | 메모리 상한 JUnit 실패. 모든 입력 호출 성공·정상 stop만으로 상한 통과를 대신할 수 없음 |
| 잘못된 핸들 전달 | stream·batch 둘 다 `SILENT_NULL` | 오류 전달 JUnit 실패. 명시적 오류가 음성 없음처럼 보일 수 있음 |

이 기준판 묶음은 **JUnit 2개 중 2개 FAIL**이다. 오류 전달 시험의 두 호출은 정상 음원의 실패 원인을 재현한 것이 아니라 통제된 잘못된 핸들 시험이다. 후속 소스는 오류 검사 범위를 확장했으나 이 기준판 당시 실행은 stream·batch 두 호출이었다.

후속 수정 네이티브의 VAD 단위시험은 Android API 35 에뮬레이터에서 **3개 통과·26개 assertion 통과**, 기존 upstream 시험 1개 제외였다. 실제 실행 로그 `mcasttalk-native-vad-final-regression.log`에 이 개수가 기록되어 있다. upstream 전체 또는 앱의 음성 서비스가 통과했다는 뜻은 아니다.

round10에서는 수정 네이티브를 포함한 실제 APK를 설치하고 본체·시험 APK 해시를 대조했다. 같은 예열·측정 프레임 수와 25프레임마다 강제 전사하는 조건에서 네이티브 heap은 109,850,080→109,849,968 bytes, **증가량 −112 bytes**로 8,388,608 bytes 상한을 통과했다. 12,000개 측정 프레임의 입력과 정상 stop도 확인했다. 이는 가속 합성 0 PCM의 메모리 상한 검사이며 순수 누수량의 직접 계측·8시간 안정성 검사가 아니다. 해제 후 heap은 22,863,184 bytes로 기록했으나 회수량 자체를 assertion으로 판정하지 않았다.

확장한 잘못된 핸들 시험은 stream·batch·add·start·stop **5개 호출 모두 `IllegalStateException`**을 확인했다. 기존 기준판은 2개 호출만 실행했으므로 5개 전부의 전후 비교가 아니다. 별도 수명 시험은 잘못된 stream의 start·add·stop 오류 3건, 동일 정상 stream의 시작→입력→강제 배출→중지 3회, 중지 후 입력 거부와 이중 해제의 안전한 정리를 확인했다. 이 무음 시험만으로 실제 음성의 최종 전사·품질을 보증하지 않는다.

## Antigravity 교차검토와 강화 시험

Antigravity에는 공개 소스 사본, 검증 본체 APK와 합성 시험의 수치 요약만 제공했다. 사용자 진단 ZIP·원문·원음·원본 로그·키는 전달하지 않았다. 독립적으로 APK와 내부 네이티브 3개, 수정 고지와 소스 8개 해시를 계산해 일치를 확인했다. 코드 검토와 해시 검증을 수행한 제2 AI 검토이며, 공인 제3자 인증이나 자체 에뮬레이터 재현 시험은 아니다. 보고서의 과도한 누수·경합 해결 표현을 검토된 호출경로로 제한하도록 Codex가 요청하고 수정 결과를 확인했다.

검토에서 실제 디코더 반복 경로 미검증과 무음 메모리 상한 8MiB의 한계를 지적했다. 따라서 1MiB 상한, 고정 25프레임 및 가변 25/50/100프레임 배출, 공개 FLEURS 7.02초 음원의 배치 추론 반복 검사를 추가했다. 이 배치 JNI는 제품에서 직접 사용하지 않으며, 수정된 JNI 소유권과 디코더 경로를 별도로 검증한다.

round11은 **4개 통과·1개 실패**했고 새 프로세스에서도 음성 검사 실패가 재현됐다. 필수 단어 6개 중 3개만 인식하여 메모리 측정 전 실패했다. 시험 설정에 제품의 한국어 `max_tokens_per_second=13.0`이 누락돼 native 기본값 6.5를 사용했다. 시험의 해당 옵션 하나만 13.0으로 보정한 round12는 **5개 통과, 8.258초**였다. 키워드·메모리 기준을 완화하지 않았으며 이전 실패를 보존했다. 이는 이 음원·설정 비교의 결과이지 빠른 발화 전체의 절단 방지 보증이 아니다.

| round12 검사 | 실제 측정 | 범위 |
|---|---:|---|
| 고정 배출 무음 12,000프레임 | heap 변화 0 bytes, 2,142ms | 1MiB 상한 통과 |
| 가변 배출 무음 12,000프레임 | heap 변화 −112 bytes, 2,198ms | 1MiB 상한 통과 |
| 실제 음성 2회 예열 후 4회 측정 | heap 증가 10,512 bytes, 마지막 2회 1,984 bytes | 각각 2MiB·512KiB 상한 통과 |
| 실제 음성 내용 확인 | 6회 모두 완료 행 1개, 52글자, 필수 단어 6/6 | 이 짧은 단일 음원의 내용 검사 |
| 명시적 오류 및 세션 생명주기 | 잘못된 호출 5종 오류, 재시작 3회, 정리 검사 통과 | 통제된 입력 조건 |

실제 음성 검사 전체 경과는 3,715ms이며 8시간 안정성 시험이 아니다. 무음의 −112 bytes나 음성의 증가가 어떤 할당자 동작에서 발생했는지는 계측하지 않았다. 공유 Silero 은닉 상태, 동시 스트림, 최초 로드 반복과 장시간 추론의 잔여 위험은 이 시험으로 제거했다고 말할 수 없다.

round12 본체는 round10과 바이트 단위로 동일한 `fba37b600fc0519e07a7289bf0a0b9a63c05b5e7d9f51f05d52502eb09885610`이다. round12 시험 APK는 `8e038840b50165c740f7db666e114ce173719cf6437978d69cf08db7846eed55`, 4,608,233 bytes다. 설치된 두 APK의 해시를 실행 직전에 검증한 영수증은 `20260923T164549.337343Z-98c04328`이다. round11 실패 시험 APK `f29ddbe9ae7262956eb3a4b05bbbbd45f94d50b21c8260fff7720d0163a13c18`과 구분한다.

Antigravity는 round11과 round12 소스 해시 및 diff를 직접 대조해 해당 옵션 외의 합격 기준이 그대로임을 확인했다. Codex가 최종 정정 보고서와 변경 검토 화면을 확인하고 지정 범위의 산출물을 승인했다. 위임 승인 기록은 로컬 증빙에 보존하며, 전역 자동승인·권한 확대나 제품 재배포 승인을 뜻하지 않는다.

## UI·마이크·미완료 범위

round8 UI 최초 23개는 18 PASS·5 FAIL, 실패 5개 재시험은 3 PASS·2 FAIL, 최종 capability 확인은 **2 PASS·1 SKIP**이었다. 마지막 PASS에는 새 미지원 기기 검사가 포함된다. Gemma 메모리 조건을 충족하지 않는 AVD에서는 활성화 시험을 SKIP했고, 별도 시험은 비활성 상태에서 한 번 터치해 설정과 런타임이 유지됨을 확인했다. 캐시 재조회와 클릭 위치 보완은 검증 기대값을 삭제하거나 성공할 때까지 재클릭하는 수정이 아니다. 원래 실패 기록을 보존했다.

실제 파일 선택→한국어 전사→영어 번역→보관함 저장→재생은 round8 최초 묶음에서 통과했다. 그러나 **가상 마이크 전체 여정은 최종 FAIL**이다. 다섯 번 중 JUnit 1회 통과도 호스트 주입기 종료 시간 초과로 전체 실행은 실패했다. 다른 실행은 전사·저장 후 오래된 UI 객체로 재열기에 실패했고 최신 실행은 녹음 중 전사 표시에서 실패했다. 최신 91.232초 녹음의 완전한 음원 전달을 확인하지 못했다. 주입기·AVD·AudioRecord 중 단독 원인은 미확정이며, 재열기 helper 변경도 이 최신 실행에서는 도달하지 못했다. 세 핵심 단어 검사는 원문 전체 정확도 검사가 아니다.

round8 당시 단위시험 767개, 정상 EOF 2개, 설치 엔진 조회 1개, 방송/시험 2개, legacy DB 5개 등의 기록은 당시 산출물 범위로 보존한다. 후속 최종 네이티브 패키지의 결과로 재사용하지 않는다. 설치 엔진 조회는 언어 인식 성공 검사가 아니며 다른 6개 언어 각 30건, 총 180건은 실제 음성 시험 미완료다.

물리 Galaxy·One UI, 현장 마이크·앱 출력 캡처, Android/iPhone 브라우저 청취, 사람의 음성 자연스러움, S23 첫 음성 p95 2,000ms와 8시간 연속 안정성은 입증하지 않았다. 사용자에게 추가 공개 승인을 요구하는 대신, 이미 요청된 공개의 품질 조건을 실제 결과로 충족해야 한다.
