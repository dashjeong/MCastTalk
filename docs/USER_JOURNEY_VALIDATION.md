# 가상 사용자 시나리오와 화면 검증

이 문서의 인물은 기능 검증을 위해 만든 가상 사용자다. 실제 사용성 조사나 실제 기기의
음성 정확도·청감 평가 결과가 아니다. 테스트에는 합성 파일명과 문장만 사용한다.
실행 여부와 결과는 [시험 보고서](TEST_REPORT.md)를 기준으로 한다.

| 가상 사용자 | 사용 흐름 | 화면·동작의 합격 조건 |
| --- | --- | --- |
| 민서 · 현장 안내 진행자 | 입력 앱 선택 → 필요하면 패키지 직접 수정 → 단독 사용 시작 → 실시간 스크립트 확대 → 지난 문장 확인 → 운영으로 복귀 | 앱 선택이 패키지 칸에 반영되고 직접 입력은 다음 앱 선택 전까지 유지된다. Wi-Fi 없이 단독 사용을 시작한다. 화면을 터치하면 자동 따라가기가 멈추고, 복귀해도 입력·방송 상태가 바뀌지 않는다. |
| 준 · 반복 청취 학습자 | 여러 파일/폴더 선택 → 번역 언어 지정 → 변환 → 실패만 재작업 → 파일 선택 → 재생·일시정지·중지 → 헤드업 → 번역·속도·글자 조절 | 파일별 진행과 실패를 구분한다. 재작업이 성공한 스크립트를 지우지 않는다. 파일과 스크립트의 해시가 맞아야 재생한다. 재생 조작은 스크립트 스크롤과 분리된다. 단어 시각이 없는 구간은 정밀 단어 동기화로 표현하지 않는다. |
| 가람 · 큰 글씨를 사용하는 단독 기기 사용자 | 360dp 폭·글자 배율 2배와 낮은 화면 높이에서 재생 → 설정 → 돌아가기 | 재생·중지·설정·복귀가 화면 밖에 갇히지 않는다. 설명보다 콘텐츠를 먼저 볼 수 있다. 기술적인 시간·해시·프레임 정보는 개발자 표시를 켰을 때 나타난다. |
| 민서 · 기록 이관 담당 | 방송 시작 시각/기간 선택 → 1,000개 페이지 → 보존 방식 선택 → 사전·스크립트 백업 검사 → 가져오기 | 활성 방송 기록 500,000개 한도를 적용한다. 백업 실패는 기존 기록을 보존하며 알린다. 손상된 날짜 백업 때문에 다른 날짜 조회를 잃지 않는다. 이관은 현재 확정 문장을 보존하고 누락·손상·잘못된 파일 매핑을 성공으로 처리하지 않는다. |
| 준 · 개발자 실험 참여자 | 개발자 표시 활성화 → 의역/표현 TTS 별도 선택 → API 사용 여부 선택 → AI 문장 확인·수정 | 기본 경로는 실험이 꺼져 있다. API 키를 화면이나 백업에 노출하지 않는다. 실시간 음성은 외부 검토를 기다리지 않는다. 사용자가 확정한 문장을 AI가 덮어쓰지 않는다. |

파일 선택·헤드업·큰 글씨·낮은 화면 높이의 합성 화면 검증은
`FileTranscriptScreensDeviceTest`, 실시간 화면 복귀와 수동 스크롤은
`TranscriptScreensDeviceTest`, 문장 사전 확인과 개발자 표시·설정 스크롤은
`SentenceMemoryScreenDeviceTest`에서 검사한다. 실제 파일 디코딩·재생·해시·SQLite 이관은
별도 기기 시험으로 검사한다. 코드나 합성 화면 시험을 8시간 실기기 무중단 시험으로 대신 표기하지 않는다.
