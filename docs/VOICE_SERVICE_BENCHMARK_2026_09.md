# 음성 서비스 비교·진단·발전 방향

조사일: 2026-09-22 KST. 현재 확인 가능한 공식 문서와 공개 사용자 글을 비교했다. 세계 시장점유율 순위나 유료 전환율을 조사한 자료는 아니며, 아래는 널리 제공되는 대표 서비스의 제품 전략 비교다. 공식 지연·정확도 수치는 공급자의 조건별 주장으로, MCastTalk에서 재현한 측정값이 아니다. 사용자 글은 개별 경험이며 불만 발생률을 뜻하지 않는다.

## 사용자가 비용을 내는 이유

인식률만으로 제품 가치를 설명하기 어렵다. 녹음 이후 문서 작성·검토·공유 시간을 줄이고, 중요한 이름·숫자를 맞추며, 다시 작업할 때 비용과 결과를 예측할 수 있는지가 핵심이라는 판단이다. 이는 아래 기능·요금·후기를 종합한 제품 기획상의 추론이며 결제 동기 설문 결과가 아니다.

| 대표 사례 | 공식적으로 확인한 강점 | 지불 가치에 대한 해석 | MCastTalk의 차이와 대응 |
|---|---|---|---|
| Otter | 회의 전사, 화자, 검색, 재생, 템플릿·업무 연동. 유료 단계에서 시간·업로드·내보내기 범위 확대 [1][2] | 회의가 끝난 뒤 자료를 정리하는 시간 절약 | 녹톡의 원음 대조·배속·검색 범위 내보내기를 강화. 녹음 60분·Android 조건은 시작 전 표시. 회의 봇 자동 참가와 클라우드 저장은 현재 제공하지 않음 |
| Notta | 전사 편집과 여러 파일 형식·공유 [3] | 언어 학습·인터뷰·회의 기록을 재사용 가능한 문서로 만들기 | TXT/SRT/WAV에 MD/JSON 추가. 원문·번역·화자·시간 선택과 번역 미완료 표시 |
| Descript | 전사 문서를 편집해 오디오·영상 편집에 연결 [4] | 익숙한 문서 조작으로 제작 시간 단축 | 문장 검색→원음 구간 듣기→직접 수정→저장의 짧은 흐름. 실제 오디오 절단·합성은 별도 기능이며 현재 문장 수정으로 원음이 바뀌지 않음 |
| Deepgram Nova-3 | 스트리밍/파일 STT, 다국어와 도메인 용어 Keyterm Prompting [5] | 이름·전문 용어 오류와 후편집 부담 감소 | 기존 인식 교정·용어 자산을 활용하되 STT 힌트, 원문 교정, 번역 사전, TTS 발음 사전을 같은 것으로 취급하지 않음. 언어 미확인은 그대로 유지 |
| ElevenLabs Scribe / TTS | STT 화자·타임스탬프·용어 지원. TTS는 표현력·장문 안정성·응답 속도에 따라 모델을 구분. 유료 상업 이용·제작 도구 [6][7][8] | 자연스러운 납품 음성과 반복 제작의 일관성, 사용 권한 | 원음 방송의 저지연과 번역 TTS의 정확성을 별도 평가. 실험실에 숫자·이름·안내문 대조 문장을 추가. 기기 음성을 ElevenLabs 수준이라고 주장하지 않음 |
| Azure Speech / Google Cloud Chirp 3 HD | 발음/사전 제어와 스트리밍 TTS 등 서비스별 제어·언어 조건 [9][10] | 브랜드·이름 발음 제어, 서비스 통합과 운영 안정성 | 공급자별 능력과 비용을 숨기지 않는 선택 구조 유지. 현 단계에서는 새 클라우드 음성 전송이나 종량제 엔진을 자동 추가하지 않음 |

요금은 결제 주기·지역·프로모션·API와 웹 제품에 따라 달라진다. 예컨대 Otter는 회의 길이와 파일 업로드를 별도로 제한하며, ElevenLabs는 크레딧과 상업 이용 조건을 구분한다 [1][8]. 이를 단순한 '분당 가격' 하나로 비교하면 사용자가 실제 부담할 재시도·추가 기능 비용을 놓친다. MCastTalk의 비교 실험은 기존 안내처럼 API 호출 그룹당 최대 3회, 공급자별 API 과금 별도이며 ChatGPT/Gemini 웹 구독과 혼동하지 않게 한다.

## 사용자 불편에서 도출한 진단

- 2026-09-11 ElevenLabs 사용자 글은 여러 생성 구간의 목소리·발음 일관성을 문제로 제기한다 [11]. 모델 문서 역시 비결정성과 문맥 연결을 설명한다 [7]. 대응: 긴 음성의 첫 문장 자연스러움만 점수화하지 않고 구간 연결·숫자·부정·이름을 듣기 항목으로 분리한다.
- 열람 시점에 약 6개월 전으로 표시된 Otter 사용자 글은 2시간 회의와 자신의 90분 실시간 한도 차이를 문의했다 [12]. 공식 요금 조건과 함께 확인해야 한다. 대응: 한도·남은 시간·중단 후 저장 상태를 사전에 알리고, 60분을 8시간으로 표시만 바꾸지 않는다.
- Notta·Otter 스토어 표본에서 확인한 저장·한도·입력 범위·검색 불편은 기존 `BENCHMARK_IMPROVEMENTS.md`에 날짜와 근거를 보존했다. 새로운 후기와 오래된 후기를 합쳐 현재 결함 비율로 계산하지 않는다.

## 이번에 반영한 개발

1. 녹톡: TXT/MD/SRT/JSON/WAV, 원문만·번역 포함·화자·시각·검색된 구간 선택, Windows 호환 TXT, 번역 대기 수와 추정 시각 표시. SRT는 검색 후에도 원음 시간축 유지, JSON은 원래 구간 순번·미확인 언어·수동 수정·시각 추정 여부 보존. JSON은 분석용 문서이며 앱 재가져오기 기능은 아니다.
2. 원음 대조: ±10초, 0.75/1/1.25/1.5배, 현재 재생 구간 표시. 재생 막대는 이동을 마칠 때 한 번만 MediaPlayer에 전달한다.
3. 정확성: 자동 감지의 미확인 문장에 파일 대표 언어를 대입하던 처리를 제거. 사용자가 수동 지정한 언어만 대체 값으로 허용한다.
4. TTS 검토: 실험실에서 한국어·영어·일본어·중국어의 숫자/단위, 이름/약어, 안내/질문 합성 문장을 불러와 기본 음성과 표현 실험을 비교한다. 자동 품질 점수나 통과 판정을 만들지 않는다.
5. 비교 번역: 기존 Gemini/OpenAI 독립 검토→교차 확인→승인/보류→문맥별 적용 흐름 유지. 일반 검토에서 사용하지 않는 빈 문맥·참고 필드를 보내지 않는다. 실제 비교에 필요한 문맥·이전 교정은 명시한 동의 범위에서만 사용한다.

## 발전 순서와 수용 기준

| 우선순위 | 다음 발전 | 실제 검증 조건 |
|---|---|---|
| P0 | 실제 API 및 원 개발 휴대폰 검증 | 비교 문장 원문·정답·두 모델 응답·채택 이유·비용/시간 기록. 숫자·부정·조건·이름 오류는 문장이 매끄러워도 실패. 마이크·Bluetooth·중단 복구·발열·배터리·Wi-Fi 혼잡을 분리 |
| P1 | 도메인별 STT 힌트와 TTS 발음 사전 | 언어·엔진별 지원 여부 확인, 정확한 토큰/구문 범위, 원문과 발음 대체문 분리, 수정 전후 A/B 듣기, 사용 해제·되돌리기. 아직 구현된 발음 사전으로 표시하지 않음 |
| P1 | 중요한 문장 표식과 근거 연결 요약 | 원문 구간을 누르면 근거 재생. 확인되지 않은 행동 항목·발언자·날짜를 생성하지 않음. 원문 수정 후 요약의 낡은 상태 표시 |
| P2 | 실시간 노트 ASR와 녹음 일시정지·분할 복구 | 하나의 PCM 시간축, 지연 시 기록 우선, 실기기 CER/WER·RTF·p95·메모리·발열 기준. 기존 60분 한도는 검증 전 유지 |
| P2 | 자동 화자분리 / 선택형 고품질 음성 | 겹침·짧은 맞장구·언어 전환 시험, 미확인 허용. 모델 라이선스·공급망·다운로드 실패·저장 공간과 기기 성능을 함께 검증 |

첨부 기획안의 600개 발화/12개 대화, RTF·언어 감지·번역 평점·복구 손실 등의 수치는 향후 수용 목표로만 취급한다. 아직 측정하지 않은 정확도나 실시간 성능을 달성했다고 기재하지 않는다. 현재 실제 API 키와 물리 Android 기기가 없어 관련 시험은 미수행이다.
