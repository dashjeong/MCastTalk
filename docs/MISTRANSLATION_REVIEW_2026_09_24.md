# 오역 검토 및 에뮬레이터 검증 — 2026-09-24

상태: 실제 오역 재검토와 원인 수정 검증. 의미 오류가 남아 품질 승인은 보류한 뒤,
사용자가 현재까지의 수정본 공개를 명시적으로 요청해 **0.2.44 Alpha 공개 절차로 전환했다**.
이는 모든 품질 조건을 통과했다는 판정이 아니다. 0.2.43 철회 기록과 실패 증거는 보존한다.

사용자의 최신 지시에 따라 다국어·실기기 검증 환경을 에뮬레이터로 대체한다.
물리 Galaxy 부재만으로 작업을 보류하지 않는다. 에뮬레이터에서 번역만 실행한 경우와
실제 음성인식·번역·음성 출력까지 실행한 경우를 구분한다. 8시간 연속 실행은 이번 결과에 포함하지 않는다.

## 이전 판정 정정

`56년째`를 `for 56 years`로 옮긴 결과를 반드시 오역이라고 단정한 것은 잘못이었다.
`-째`는 순서뿐 아니라 기간의 뜻도 갖는다. 정확한 시작일 또는 만 경과 연수와의 대조가
없는 해당 구어 문맥에서 기간 해석을 허용한다.
[국립국어원 온라인가나다 답변](https://korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=98&pageIndex=1&qna_seq=323790)

`haven't taken a day off`도 매일 계속했다는 의미를 표현한다. 이를 거부한 종전 정규식은
수정된 별도 평가 기준으로 교체하되 기존 시험 파일·로그·실패 기록은 덮어쓰지 않는다.

종전 검사가 놓친 시제·상 문제도 별도 검토 대상이다.

## 실제 오류와 분리할 위험

- `몇 분이 계속 서 계셔가지고…`를 `a few minutes`로 옮긴 것은 사람 수를 시간으로
  바꾼 실제 오류다. 원문을 수정하지 않고 제한된 주어·높임 서술어 구조를 문법 참고로 제공한다.
- `정전체제`를 `inter-war system`으로 옮긴 것은 실제 오류다. 군사 문맥과 전기 정전·정전기
  반례를 함께 비교한다.
- 공개 사전의 `정전=power outage`가 군사 문맥에 힌트로 들어갈 위험을 확인했다.
  이전 round15/16 시험에는 사전 힌트가 없었으므로 이전 실패의 원인이라고 소급 단정하지 않는다.
- 선택적 보완 경로의 800ms 검토 제한은 실제 로컬 추론이 완료되기 전에 취소될 수 있었다.
  보완 옵션이 켜진 경로에서만 공정 큐의 대기·추론 상한을 존중하도록 수정한다.
  자동 문체에서 검토를 생략하는 실험은 아래 실제 의미 검사에서 오류를 남겨 채택하지 않는다.

### 실제 경로에서 추가로 확인한 원인

정확한 검토 결과 `Seventy-three years have passed since the gunfire...`가 원문의
`73`과 다르다는 이유로 거부되어 `The total scores of the Korean War...` 초안으로
되돌아갔다. 이는 모델의 생성 실패와 별개인 숫자 보호 검사의 표기 비교 오류다.
`Nine`과 `9`도 같은 문제가 있었다. 영어 기수 표기를 비교할 때만 정규화하고,
숫자 변경·누락·순서·중복 보호는 유지하는 후속 수정을 검증한다. 이 검사는
`4년째/만 3년`의 의미 관계까지 판정하지 않는다.

사전 없는 검토에서는 `정전`을 ceasefire로 번역했으나 공개 사전 힌트를 넣자 power outage로
바뀌었다. 반대로 냉장고 문장은 사전 힌트가 없을 때 ceasefire, 있을 때 power outage였다.
이를 근거로 해당 공개 다의어 항목은 현재 문장의 전기 맥락이 명시된 경우에만 힌트로

### 추가 반례 보완

코드 교차검토에서 `1-million`을 `1`로 비교할 수 있는 숫자 보호 허점과,
`three and five`를 한 숫자처럼 읽어 올바른 보완을 거부하는 반례를 수정했다.
또 `전원`(모든 인원), `전기`(인물의 생애), `전력`(힘을 다함), `조명`(주목)을
단독 전기 문맥 근거로 쓰지 않도록 공개 사전 규칙을 좁혔다. 이 규칙은 제한된 어휘 단서이며
범용 의미 판별기가 아니다. 사용자가 편집한 사전 항목의 우선권은 보존한다.

### 재현 명령과 증거 구성

```sh
./gradlew testDebugUnitTest :core:stream:test :core:translation:test \
  :app:testAlphaUnitTest :app:lintAlpha :app:assembleAlpha \
  :app:assembleAlphaAndroidTest :app:verifyPackagedThirdPartyLicenseAssets \
  --offline --max-workers=1
```

실행별 로컬 증거에는 정확한 ADB instrumentation 명령, 시작/종료 시각, JUnit 완료 상태,
설치 전후 본체·시험 APK 해시, 고정 입력 해시, 실제 원문·출력·항목 판정, 별도 AI 의미 감사가 있다.
미완료·FAIL·미지원 실행도 보존한다. 모델 준비를 측정한 시험과 캐시 재사용 시험을 구분한다.
이 자료는 사용자의 비공개 진단 ZIP·키·계정 정보를 포함하지 않으며 공개 저장소에는
원본 실행 로그·APK·모델을 올리지 않는다.

기존 배포 인증서 서명·16KiB 정렬을 검증하고 같은 두 파일을 설치했다.

실제 공급자·공정 큐·숫자 보호·AUTO·공개 사전 통합 시험은 26/26 요청을 77.887초에 완료했다.
**검토 26회 모두 채택, 생략/실패/시간 초과/보호 거부 각 0**이었다.
자동 의미 항목은 23/26이며, 기존 2개 정규식 오탐과 명시적 연차 관계 오류 1개가 남아
JUnit 품질 판정은 **FAIL**이다. 실행 완료를 번역 품질 통과로 바꾸지 않는다.
이 경로는 단일 ko→en 요청을 순서대로 넣은 공급자 통합 시험이며 방송 서비스·다언어 동시 부하
전체를 재현한 것은 아니다. 추가 검토 대기는 옵션 화면에 고지한다.

같은 최종 APK에서 ML Kit 7원어 21건(1.236초), Gemma 지원 5원어 15건(38.855초)을 다시 실행했다.
각 원문·결과는 round19b의 해당 공급자 결과와 전부 동일했다. fr/de Gemma 6건은 미지원 미실행이다.
이 두 JUnit PASS는 **번역 요청의 실행 완료**를 확인하며 품질 필드는 `REVIEW_REQUIRED`다.
따라서 앞서 확인한 입장료·시간 관계 문제를 해결했다고 기록하지 않는다.

## 공개 후보 0.2.44 Alpha (Round21)

사용자의 현재 수정본 공개 요청 후 제품 동작 코드는 고정하고 버전을 `0.2.44-alpha`,
`versionCode 50`으로 올렸다. 기존 0.2.43 배포를 재활성화하지 않는다.
전체 빌드 게이트는 4분 48초에 성공했다(615 tasks: 50 executed, 565 up-to-date).
JUnit 스냅샷 283 suite/1,887회 기록의 실패·오류·skip은 0이며 이전 결과 재사용을 포함한다.

- 공개 파일: `MCastTalk-0.2.44-alpha.apk`, 96,342,080 bytes
- 제품 SHA-256: `4c344a8375a7ebb0f5724eac79b18b3b8c3a808c21a3e97ade8de2092c0efa0c`
- 시험 APK SHA-256: `f92821327e40e76758aab7648fc6537bdd81dc877f613d83ccb35e3cd46ef244`
- 기존 배포 인증서 서명과 16KiB 정렬을 확인했다. Antigravity도 같은 APK를 읽기 전용 명령으로
  독립 확인해 해시·크기·패키지·버전·인증서·정렬이 일치함을 보고했다. 품질 인증과는 구분한다.
- 기존 code49 시험 설치본 위에 실제 `adb install -r` 업데이트가 성공했다. 사용자 설정·자료 전체의
  0.2.42→0.2.44 마이그레이션을 새로 전수 검증했다는 뜻은 아니다.

정확히 이 APK의 사용자 경로 4건을 **164.518초에 모두 통과**했다.

1. 기록된 한국어 음성 → 실제 인식·영어 번역·TTS·청취 PCM 도달
2. 운영자의 시험 버튼으로 같은 실제 음성 경로 완료 후 다시 실행
3. 파일 선택 → 실제 한국어 전사·영어 번역 → 보관함 재생
4. 공개 사전의 모호한 의미 제한 및 사용자 편집 항목 우선권·복원

인증서·정렬 성공이나 이 네 경로의 성공을 모든 UI, 모든 언어 음성, 장시간 운영 성공으로
확대하지 않는다. 이전 엄격한 파형 검사 실패, 전체 210개 음성 코퍼스 미완료, 남은 의미 오류는 유지한다.

공개 APK에서 의미 통합 26건(78.181초), ML Kit 7원어 21건(1.264초), Gemma 5원어 15건
(38.560초)을 실제 재실행했다. 원문·각 최종 출력은 Round20과 전부 같았다.
의미 통합은 26회 전부 검토·채택했지만 항목 검사 23/26으로 **FAIL 유지**다.
기존 전건 AI 대조의 의미 보존 24/명확 오류 1/인용 중의성 1 판정을 동일 출력에 대응시켰다.
ML Kit·Gemma 시험의 PASS는 실행 완료이며 의미 정확도 승인이 아니다. Gemma fr/de 6건은 미지원으로
실행하지 않았다. 실행 전후 설치본 SHA-256은 공개 APK와 일치했다.

공개 범위는 [0.2.44 Alpha 릴리스 설명](RELEASE_0_2_44.md)에 명시한다. 사용자가 현재까지의
수정본 공개를 요청했으므로 알려진 제한을 포함한 Alpha로 제공하며, 실패를 합격으로 바꾸지 않는다.
