# 코드 구조·안정성·용량 최적화

## 책임 구분

| 층 | 소유 책임 | 의존 규칙 |
|---|---|---|
| 공통 core | 오디오/스트림/서버/번역 계약과 처리 | 화면·Activity·특정 제품 이름에 의존하지 않음 |
| provider | Android, ML Kit, Moonshine, Gemma 구현 | 공통 계약을 구현. 공급자 장애를 다른 채널까지 확산하지 않음 |
| 서비스별 조정 | VoiceNoteViewModel 등 녹톡·방송·파일 작업 | 취소·작업 독점·저장·엔진 선택 조정 |
| 서비스 특화 데이터 | VoiceNoteFormat/Translation/Repository | 문장 수정, 번역 재개, 원자적 저장 계약 |
| 분리한 파일 작업 | VoiceNoteAudioFile / VoiceNoteExport | PCM 복구와 문서 출력 분리. 내보내기는 한 코드 경로의 스트리밍 Writer |
| 화면 조립 | VoiceNoteScreen / ExportPanel / PlaybackControls | 시스템 파일 선택기, 옵션 표시, 재생 조작을 분리. 다른 서비스의 FileAudioPlayback을 공통 사용 |

분업은 파일 이름 분류보다 변경 책임과 테스트 경계로 관리한다. 외부 엔진 변경은 provider, 문서 포맷은 Export, UI 배치는 Panel에 국한한다. 작은 화면 구성요소를 별도 Gradle 모듈로 만드는 빌드 비용은 추가하지 않았다.

## 실제 정리·최적화

- 중복된 전체 문자열 TXT/SRT 빌더를 운영 코드에서 제거. 기존 회귀시험도 새 스트리밍 구현을 호출하도록 연결했다.
- 내보내기 전체 String→UTF-8 ByteArray 동시 복제를 제거. 각 구간과 WAV 64KB 버퍼만 출력한다. 미완성 출력과 원본 보존 상태를 구분한다.
- 검색마다 문장별 임시 리스트를 생성하지 않고 세 필드를 직접 검색한다.
- 보관함은 JsonReader로 전사 배열을 건너뛰어 요약만 읽는다. 노트마다 최대 4MB JSON 전체와 문장 객체를 만드는 일을 제거한다.
- 파일 선택기의 프로세스 복원에는 ID·옵션·SHA256만 저장한다. 큰 전사는 SavedState에 넣지 않고 재개 시 원본 개정이 일치하는지 확인한다.
- 자막 공백 정규식을 구간별로 컴파일하지 않고 공유한다.
- 재생 막대 이동 중 반복적인 MediaPlayer seek를 제거하고 손을 놓을 때 한 번 전달한다.
- 일반 클라우드 검토에서 사용하지 않는 빈 문맥·참고 문장 필드를 제외한다. 실제 문맥 검증의 필드를 삭제하지 않는다.
- 최적화 빌드의 Android 시험이 직접 호출하는 ScrollKt/ScrollState ABI만 보존한다. 축소를 끄거나 전체 Compose를 keep하는 방식은 쓰지 않는다.

## 용량 진단과 회귀 기준

추가 개선 전 기준 E unsigned APK: 96,022,663 bytes, SHA256 `3ba893d6c391cd4c9aa7cb827dcafc4f48f7006952cc58dac88688238d32e728`. 그 전 D는 95,924,131 bytes였다. 서로 다른 소스이므로 두 수치 차이를 이번 최적화 성과로 계산하지 않는다.

주요 용량은 LiteRT-LM 약21.5MB, ONNX Runtime 약19.3MB, ML Kit 번역 약16.4MB, Moonshine 약11.1MB, RNNoise 약5.6MB의 네이티브 코드/가중치다. RNNoise의 약5.55MB는 읽기 전용 모델 데이터이며 제거 가능한 디버그 심볼이 아니다. ARM64 한정·R8·리소스 축소는 기존에 적용돼 있었다. 구조 분리만으로 APK 용량 감소를 주장하지 않는다.

`scripts/audit-apk-size.py`는 APK/DEX/native/assets/res 크기, 상위 파일과 SHA256을 기록하고 110MB APK·18MB DEX 예산을 넘으면 실패한다. 현재 약96MB 기준에서 새 대형 의존성의 무심한 추가를 막는 회귀 상한이며, 크기 감소나 실행 성능 인증 수치가 아니다. 다음 인계에서 같은 ABI/변형의 변경 전후 크기를 비교한다.

큰 폭의 감량은 선택형 엔진 배포, 축소된 ONNX 연산자 구성, 계측 시험 ABI와 배포 ABI 분리를 검증해야 가능하다. 지금 필수 연산자·오프라인 자산·라이선스를 제거하면 기능이나 재현성을 잃는다. native/DEX 강제 압축은 설치 공간·첫 실행과 교환 관계가 있으므로 다운로드 숫자만 줄이려고 적용하지 않는다.

## 리뷰에서 수정한 불안정성

자동 언어 감지의 잘못된 대체 언어, 시스템 파일 선택 중 내보내기 대상 변경, 출력 중 취소/실패의 성공 오인, 자막 구간 순번과 원음 시간 혼동을 방어한다. 기존 녹음 AtomicFile·복구, 작업 취소, 비교 학습의 승인/되돌리기 보호는 그대로 회귀검증한다. UI 실패 증거에는 별도 Pixel Launcher ANR가 있어 폐기용 CI에서만 런처를 격리하고 앱 자체 오류를 숨기지 않는다.
