# 오프라인 관리자·사용자·게스트 계정

2026-09-19 사용자 추가 요구에 따른 구현 계약. **로컬 미리보기 구현이며 출시 승인 아님**.

## 최초 설정과 저장

설치 후 첫 실행은 작업 공간 선택 → Windows 관리자 설정창 → 서버 시작 → 웹 로그인
순서다. 설치한 사용자가 관리자 아이디·표시 이름·비밀번호와 확인값을 직접 입력한다.
기본 admin 계정/비밀번호, 익명 관리자 선점, HTTP 초기 관리자 생성 API는 없다.
취소하면 서버를 시작하지 않는다. 기존 계정 저장소는 재시작 시 유지한다.

계정은 선택한 데이터 폴더의 `config/security` 아래에 저장한다. 모델·음성 파일과
계정 정보를 구분하고, 외부 인증 서비스·이메일 확인·인터넷 접속에 의존하지 않는다.
저장소 독점 잠금으로 동일 작업 공간에 대한 중복 프로세스 쓰기를 막는다. 변경은
원자적으로 저장하며 손상·부분 초기화는 자동 계정 재생성 대신 오류로 처리한다.

아이디는 정규화된 영문 URL-safe 식별자(3~32자), 표시 이름은 최대 64자다.
비밀번호는 사용자 요청에 따라 8~128자로 받으며 공백을 자동 제거하지 않는다. JDK 표준의
PBKDF2-HMAC-SHA-256, 600,000회, 개별 무작위 salt 및 상수시간 비교를 사용한다.
평문 비밀번호는 저장·로그·계정 응답에 포함하지 않는다. 이는 Argon2와의 성능
비교를 완료했다는 뜻이 아니라 현재 오프라인 JDK 배포의 검증 가능한 구현 선택이다.
해시 비용은 실제 장비에서 확인하고 알고리즘/비용을 저장해 향후 이행 가능하게 한다.
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

## 역할과 권한

| 역할 | 회의/채팅 | 계정 관리 |
|---|---|---|
| ADMIN | 로그인 후 현재 허용된 회의 기능 | 계정 생성·목록·표시 이름/권한/활성 상태 변경·비밀번호 재설정·게스트 발급 |
| USER | 로그인 후 회의 및 전체/개인 채팅 | 본인 비밀번호 변경, 다른 계정 관리 불가 |
| GUEST | 관리자가 지정한 한 회의실에 유효기간 동안 참가 | 본인 비밀번호 변경만; 관리자·사용자 관리 불가 |

게스트도 관리자가 발급한 계정이다. 익명 입장·공개 가입은 기본 제공하지 않는다.
게스트 발급 UI의 초기 만료값은 24시간이며 실제 만료는 서버가 검사한다.
최종 활성 관리자의 비활성화/강등/삭제와 관리자 본인의 비활성화/강등/삭제를
금지한다. 관리 UI는 삭제 대신 활성/비활성 전환을 제공한다. 클라이언트가 제출한 role이나
표시 이름으로 권한을 얻지 못하며, 회의 표시 이름은 인증된 계정에서 가져온다.
참가자 ID/접속 presence ID와 영구 계정 ID는 다른 개념이다.

## 세션과 차단

로그인은 256-bit 무작위 opaque token을 발급한다. 브라우저는 HttpOnly,
SameSite=Strict 쿠키를 사용하고 localStorage에 인증 정보를 저장하지 않는다.
서버에는 token hash와 세션 메타데이터만 메모리에 보관한다. 재시작 시 세션은
유효하지 않으며 다시 로그인해야 한다. 기본 idle 30분/absolute 8시간보다 게스트
만료가 이르면 게스트 만료를 우선한다. 로그인 실패 횟수, 해시 동시성, 계정/세션
개수는 제한하며 실패 사유로 계정 존재 여부를 노출하지 않는다.

권한 변경·비활성화·암호 재설정 시 해당 계정의 기존 세션을 철회한다. 로그아웃은
해당 세션을 철회한다. 같은 브라우저에서 다른 계정으로 로그인하면 교체 전 세션도
철회한다. 실패한 로그인은 기존 세션을 훼손하지 않는다. 다른 탭은 인증 변경을
통지받아 이전 계정의 회의/비공개 채팅을 비우고 서버 세션을 다시 확인한다.
WebSocket 입장, 수신 명령, 메시지 전달에 유효 계정/세션을
검사해 오래된 접속이 계속 채팅을 받지 못하도록 한다. 전체/개인 채팅의 room과
presence ACL은 로그인 여부와 별도로 계속 적용한다.

수동 세션 조회·WebSocket heartbeat·메시지 수신만으로 유휴 시간이 연장되지 않는다.
여러 세션이 동시에 만료될 때 철회 통지는 재귀 호출 대신 병합 큐에서 처리한다.

모든 변경 HTTP 요청에는 동일 출처 Host/Origin과 JSON 입력 크기/시간 제한을
적용한다. HTTP 초기화/자가가입/암호를 URL에 넣는 방법은 허용하지 않는다.
현재는 loopback HTTP이므로 TLS 보호를 제공한다고 주장하지 않는다. LAN/WAN은
HTTPS/WSS, Secure 쿠키, 방 입장권/역할 검증을 완료하기 전 계속 비활성화한다.
[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

## 수용 시험

- 최초 관리자 지정, 취소, 재시작 시 보존, 기존 store 덮어쓰기 금지.
- 평문 부재, salt/해시 검증, 틀린 비밀번호, 대소문자/중복 아이디, 입력 경계.
- 저장 실패 시 기존 상태 보존, 손상 파일/초기화 marker, 중복 프로세스 잠금.
- ADMIN만 CRUD 가능, 마지막 관리자 보호, USER/GUEST의 권한 상승 차단.
- 게스트 단일 방·만료, 세션 idle/absolute, logout/비활성/reset 후 WS 종료.
- 쿠키 속성, CSRF/외부 Origin 차단, 메시지 수신 직전 권한 재검증.
- 실제 Edge에서 로그인→입장→전체/개인 채팅→로그아웃, 관리자 생성·변경 흐름.
- Windows 최초 관리자 GUI는 callback 단위 시험과 실제 사용자 GUI 검수를 구분.

자동 시험과 실제 app-image/Edge 실행 결과는 루트 `VERIFICATION_2026-09-19.md`에
별도로 기록한다. 브라우저 시험 계정 생성기는 test source에만 있으며 제품 jar/EXE에
포함하지 않는다. 따라서 시험용 계정을 기본 관리자 계정으로 배포하지 않는다.

최초 관리자 비밀번호 분실을 우회하는 기본 계정이나 자동 재설정은 제공하지 않는다.
오프라인 복구/백업, MFA, 감사 로그 보존, 실제 Windows ACL/보안 진단,
인터넷 공개 보안 검수는 후속 출시 항목으로 별도 확인한다.
