# 검증 가능한 품질 기준

> 2026-09-19 / 개발 기준 / 최종 모델 선택·출시 승인 아님

## 모델을 선택하는 순서

1. 오프라인 실행과 재배포 조건을 충족한 모델·런타임·토크나이저·음성 팩을 파일 hash로 고정한다.
2. 언어별 정확도·발음·명료도 기준을 먼저 통과시킨다. 평균 점수로 취약 언어를 숨기지 않는다.
3. 같은 PC에서 동시 발화·출력 언어·영상 처리까지 포함한 응답시간과 자원 사용량을 비교한다.
4. 지속 부하를 감당한 조합을 하드웨어별 기본값으로 선택한다. 단독 모델 속도로 전체 회의 동시성을 추정하지 않는다.

최고 품질 프로필과 반응성 우선 프로필은 같은 품질 하한선을 사용한다. 설정 변경이 정확도나 지연에 미치는 영향은 실측값이 있을 때 표시한다. 현재 후보는 `MODEL_CANDIDATES.md`에 있으며 실제 추론 성능 확정값은 아직 없다.

## Gate 1 증거 v2

`contracts/benchmark-evidence.schema.json`과 bootstrap 요약기는 다음을 요구한다.

- 모델, 런타임, 설정, 데이터셋, 평가기, 부하 조건의 SHA-256.
- 하드웨어 fingerprint, suite 버전, 모든 개별 case 식별자와 품질 metric.
- STT/TTS의 전체 요구 언어와 NMT의 모든 ordered pair. 4언어이면 12방향이다.
- STT RTF는 입력 음성 길이, TTS RTF는 생성된 출력 음성 길이를 분모로 사용한다.
- 방향별/언어별 sample 수와 p50/p95를 유지한다.

비교할 후보끼리는 hardware, suite, case 집합, dataset, evaluator, workload, 품질 metric이 일치해야 한다. 모델·런타임·설정은 비교 실험의 독립변수가 될 수 있으므로 hash를 기록하되 동일하다고 강제하지 않는다. workload 명세는 고정할 decoding 조건, cold/warm 구간, N/S/L/V, 장면 길이, 영상 해상도·fps, AC/배터리 상태를 명시해야 한다. 한 사례씩 넣은 contract 테스트는 성능 평가 결과가 아니다.

요약기는 증거의 형식과 비교 가능성만 검증하며 `releaseApproved=false`를 반환한다. 실제 파일 hash와 실행 결과의 결합, 충분한 표본 수, 실패율, 장시간 부하, 원어민 평가를 완료해야 모델을 선택할 수 있다. 사람이 임의로 입력한 점수나 mock 산출물로 출시를 승인하지 않는다.

backend calibration은 모델 hash와 해당 장치의 driver/runtime/settings까지 일치해야 한다. correctness 실패, 10분 미만 지속 시험, thermal throttle, 유한하지 않은 측정값은 선택에서 제외한다. 모델이 없으면 unavailable이고 임의의 번역·무음으로 성공 처리하지 않는다.

## 회의·채팅 수용 조건

| 항목 | 통과 조건 |
|---|---|
| 전체 채팅 | 같은 방 현재 참가자에게만 도착; 발신자·언어·서버 시각 표시 |
| 지정 상대 채팅 | 서버가 발신자와 지정 수신자에게만 전송; 제3자·다른 방 미수신 |
| 수신자 이탈 | 전송 대상이 사라지면 오류 표시; 전체 전송으로 자동 변경하지 않음 |
| 동명이인·직접 채팅 | 표시 이름 외 계정/접속 식별, 검색·비공개 바로가기, draft 대상 변경 확인·취소; 같은 이름의 다른 계정 미수신 |
| 운영 상태 | ADMIN만 접근, 실제 집계·자원과 미지원 기능 구분; room/account/path/chat 미노출; 조회로 idle 연장 금지; 관측 실패는 unknown |
| 접속 세대 | 동일 참가자 ID로 재입장하더라도 이전 개인 메시지의 수신 권한을 이어받지 않음; 새 세대 명시 선택 필요 |
| 요청 출처 | loopback이라도 임의 웹 Origin 및 Host를 차단; 이 검사는 사용자 인증의 대체물이 아님 |
| 메시지 입력 | 비어 있는/과도한 길이 거부, HTML은 문자 그대로 렌더링, 오류 후 연결 유지 |
| 언어 처리 | 원문을 보존하고 원문에서 각 대상 언어로 직접 번역; 원문/번역 구분 |
| 비공개 번역 | 대상 언어 추출·캐시·로그·자막·TTS도 같은 ACL을 지킴; 방 전체 음성 track에 노출하지 않음 |
| 연결 소유권 | 중복 입장·오래된 disconnect가 정상 세션을 삭제하지 않음 |
| 느린 수신자 | bounded queue/timeout으로 해당 연결만 격리; 다른 참가자 전달 유지 |
| 미디어 | 실제 권한과 track 상태에 따라 버튼 상태 변경; 준비 전에는 사용 불가 사유 표시 |
| 개인정보 | 현재 채팅 영구 저장·서버 녹음 없음; 이후 보관은 명시된 정책·동의·삭제 기능 필요 |

## 검증 단계

현재 loopback UI·제어·원문 채팅 검증 후 실제 local AI worker, 2인 HTTPS LAN 음성 통합, 4인 다국어 영상회의, 장비별 장시간 부하, 완전 오프라인 설치, WAN/TURN 시험 순서로 진행한다. 물리 장치·원어민·사용자 시험을 AI 역할별 리뷰로 대체하지 않는다. P0/P1 미해결 0, 핵심 시나리오 통과, 지원 범위와 알려진 제한을 기록한 뒤 출시한다.
