# 실시간 음성 지연 및 이중 원음 언어 개선

기준 커밋: bf02a27. 기존 r6 설치본은 보존했다. 이번 r7의 구현·검증 결과와
정확한 설치본은 `RESOURCE_LANGUAGE_VERIFICATION_2026-09-23.md`에 기록한다.

## 확인한 병목

- 발화마다 Whisper CLI/모델을 재기동하며 고정 512 audio context를 계산.
- Qwen4B 번역 3개와 TTS 3개를 직렬 실행하고 전체 완료 뒤에만 브라우저 전달.
- 첫 요청에 전체 번들 검증·모델 로딩·중국어 TTS 로딩이 몰림.
- 백엔드별 실제 수치 없이 네 언어를 모두 제공하고 큐가 늘어날 수 있음.
- 원음 재생 정책이 참가자별 언어를 고려하지 않는 전역 정책임.

언어별 즉시 전달. ASR 약 2.1–2.4초, 첫 번역 음성 4.9–5.2초, 4언어 전체 약 8초.
이는 브라우저/VAD/입력 발화 시간을 제외한 엔진 지연이며 아직 실시간 합격이 아니다.

## 구현 내용

1. Python 점진적 caption/audio 이벤트 및 TTS 1-lane overlap, ASR 적응 context 구현.
2. JVM의 bounded 스트림 소비, 수신자/presence 보호, 시작 시 warmup 구현.
3. 기본 청취 언어 + 추가 원음 유지 언어 1개. 이해 가능한 음성은 정상 원음,
   자막은 원문, 불필요한 MT/TTS 제외. 실제 발화 언어는 별도 명시한다.
4. 모르는 언어는 원음 배경 음량/통역 우선, 통역만/원음만/자막만 선택 유지.
   원음 언어 판정은 참가자의 실제 발화 언어 설정 기준이며 자동 판별을 주장하지 않는다.
5. warmup 실측 기반 권장 회의 언어 수/지원 언어 선택 및 QoS 정책 추가.
   목표는 짧은 발화 종료 후 음성 지연 5초 이내. 측정은 보장이 아니며 부하에 따라 경고한다.
   기본 품질 우선, 권장 초과 고급 시험은 운영자의 명시적 확인 필요. 개인 원음 유지 언어는
   실제 번역 작업 수 산정에 반영한다. 실제 장시간 부하/인간 품질 검수와 구분한다.
6. 단위/프로토콜/음량 정책/개별 메시지/이탈 세션/설정 변경/과부하 회귀 및 실제 모델 브라우저 시험.
7. 새 r7 EXE를 생성하고, 정확한 새 EXE로 인터넷 차단 Windows 검증을 수행한다.

## 사용자 정정 반영: 언어 설정 단계에서 용량 관리

- 통역 도중 언어별 수신자를 잘라내는 방식은 사용하지 않는다. 회의 참가 전 HTTP 사전 검사,
  실제 참가/언어 변경 시 membership lock 내부의 원자적 검사를 적용한다. 거절된 설정은
  저장하지 않고 기존 참석/언어를 보존한다. 운영 정책을 줄여 기존 참석자의 언어를 제외하는
  변경 역시 거절하고 원래 정책으로 복원한다.
- 회의 언어 개수와 언어 체크박스를 분리한다. 자동은 최대 5개를 기본으로 하되 실제 설치 모델과
  실측 자원 권장 이내로 한정한다. 개수 계산은 5/7/10 등으로 확장 가능하고 단위 시험으로 검증한다.
  **현재 실제 STT/MT/TTS 번들은 한국어/영어/일본어/중국어 4개만 지원한다.** 5/7/10은
  모델 팩이 없으므로 화면에서 선택 불가이며, 일반화된 용량 계산 시험을 실제 10언어 시험으로 부르지 않는다.
- 시작 시 공개 합성 발화 3초씩 네 건을 실제 STT→MT→TTS로 측정한다. 20% 여유와 VAD/전달
  800ms 예산을 더한 보수적 추정이다. 이는 p95/인간 발화/정확도 보장이 아니다.
- 최근 최대 8개 처리 결과는 권장에 반영하되 현재 확정된 언어 개수를 자동 축소하지 않는다.
  GPU→CPU 전환 시 과거 GPU 권장을 무효화하고 재시작/재측정을 안내한다. 언어 수 외의 동시 발화
  과부하에는 명시적 대기/실패 안내가 여전히 필요하며 무제한 동시 발화를 보장하지 않는다.
- 정책은 이번 서버 실행 동안만 유지하고 재시작하면 재측정/품질 우선으로 돌아간다.
- 기존 데이터 폴더의 관리형 worker 경로는 새 설치 앱의 SHA 검증된 worker 코드로 실행하며
  기존 모델/계정/운영 설정 파일을 덮어쓰지 않는다. 사용자가 지정한 별도 worker 경로는 보존한다.

검증: Windows 전체 162개 및 관련 46개 회귀 후 최종 전체 163개 재통과,
worker Python 48개, Node 26개, packaging 77개, bootstrap 38개 통과.
실제 모델·브라우저 통합 31개 통과. 개발 PC 합성 발화 시작→음성 재생은 양방향
8,316ms / 11,129ms였다. 기존 VM 31–33초와는 실행 환경이 달라 동일 환경의 배율 개선을
단정하지 않는다. 처리 최적화 효과와 목표 5초 미달을 구분한다.
새 EXE 인터넷 차단 Windows 시험은 06:48 KST PASS. 실제 모델/브라우저 46개/
재실행/제거·시험 데이터 보존을 검증했다. VM 음성 지연은 15.6초 / 30.8초로
목표 미달이다. 정확한 범위와 설치본 SHA는 위 결과 보고서를 따른다.
