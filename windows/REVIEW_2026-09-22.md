# Windows 0.4.0 인계 검토·보완 결과

검토자: Codex. 대상: `ANTIGRAVITY-WINDOWS-040-MEDIA-HUB-20260922-V1`.
실제 공동 합의는 상대 검토자의 증거 기반 회신 후에만 성립한다.
커밋/푸시/PR/공개 배포는 사용자에게 결과 보고하고 승인받기 전까지 금지한다.

## 범위와 재현 원칙

- Windows `host`, `bootstrap`, `worker`, `packaging`과 기존 모바일 코어 의존성.
- 사용자/게스트/관리자/운영자별 독립 검증 시나리오 20개 이상. 동일 검사 반복을 품질 증거로 부풀리지 않는다.
- 별도 임시 데이터와 시험 계정만 사용. 실제 설치본과 사용자의 관리자 계정/데이터는 변경하지 않는다.
- Windows 호스트 위 격리된 브라우저/계정 시험은 새 Windows 가상 머신 시험이나 인간 사용자 인수 시험과 다르다.
- 모바일 420개 테스트, 이전 Windows 0.3.1 결과, 모델 제공자의 지연 주장은 이번 Windows 결과로 합산하지 않는다.
- 원본 스냅샷 및 명령/종료 코드/시간/로그는 Git 제외 `.run/review-20260922/`에 보존한다.

## 최초 발견 기록

1. 청취 WebSocket이 계정/게스트 회의실 제한/만료/관리자 해제 검사를 우회한다.
2. 웹 앱 초기화 부근 괄호 누락 의심 — 구문 검사와 브라우저에서 확인한다.
3. 클라이언트가 작성한 번역 자막을 서버 추론 결과처럼 전체 회의에 중계한다.
4. 임의 길이 바이너리 PCM, 발화자/순서 없는 재생, 번역 없는 원음 감쇠, 마이크 권한 요청 중 퇴장 경쟁 상태를 검토한다.

## 성능 관측 — 제한된 제어 평면만 측정

동일 PC loopback에서 순차 PING/PONG **100회**: p50 **1.7ms**, p95 **2.7ms**,
p99 **3.8ms**, 최대 **4.4ms**. 합성 원문 채팅 **50건**의 응답 순서도 확인했다.
JVM 사용 heap은 약 61.1MB → 65.3MB였다. 이는 짧은 구간의 관측값이며 누수 없음의 증명은 아니다.
**음성 종단 지연, 번역 속도/정확도, GPU 가속, 최대 동시 인원, 지속 부하·발열 시험이 아니다.**
GitHub 스타/제공자 벤치마크를 이 PC의 실측 품질로 대체하지 않았다.
